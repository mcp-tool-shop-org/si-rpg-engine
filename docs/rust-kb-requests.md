# Requests to the Rust knowledge base

The Director runs a second session that builds a Rust knowledge base for this engine and acts as researcher and archivist. This file is how the coordinator asks it questions. Each request names the slice that needs the answer, states the question so it can be answered with a citation to the crate's source or docs at the pinned version, and says where the answer should land. Answers go in `docs/rust-kb-answers.md` under the same number, with the source path or URL and the version checked. The pins: `rapier3d-f64` 0.35.3 with `enhanced-determinism`, Rust 1.98.1, target `wasm32-unknown-unknown`, relaxed SIMD off.

## Open

1. **T2 restore — warm-start impulses.** After `solver_restore` rebuilds bodies from a snapshot and runs one `CollisionPipeline::step`, can the warm-start impulses in each `ContactManifold`'s `points[i].data` be written through a public path (`NarrowPhase::contact_pairs_mut` or equivalent) so the next `PhysicsWorld::step` warm-starts exactly as the uninterrupted run did? The engine already zeroes them through `zero_manifolds` in `solver/src/rapier_law.rs`, so mutation exists; the question is whether every field the solver reads at warm-start (`warmstart_impulse`, `warmstart_tangent_impulse`, `warmstart_twist_impulse`, `warmstart_tangent_world`, and anything else) is reachable and whether the solver keeps any other per-contact state outside the manifold points.
2. **T2 restore — sleep state.** What is the complete activation state of a `RigidBody` at 0.35.3 (`RigidBodyActivation`: `time_since_can_sleep`, `sleeping`, thresholds, anything else), and which public methods set each without side effects on the island manager? Does `IslandManager` hold state that survives a step and is not derivable from the bodies' activation (for example island membership or an active-set order that affects solver iteration order and therefore results)?
3. **T2 restore — broad phase.** Does `BroadPhaseBvh` keep state across steps that affects which pairs are reported or in what order (change-detection skins, leaf order, a pending-update list), such that a world rebuilt from bodies and stepped once through `CollisionPipeline` can report pairs in a different order from the uninterrupted world? If yes, is there a public way to rebuild it fully each step, and what does `enhanced-determinism` guarantee about iteration order in the narrow phase and the solver?
4. **T2 restore — serde.** With the `serde-serialize` feature, is the serialization of `PhysicsWorld` (or of `RigidBodySet`, `ColliderSet`, `NarrowPhase`, `IslandManager`, `BroadPhaseBvh` separately) canonical and byte-stable across runs and platforms at 0.35.3, or does it include hash-map ordering or allocator-dependent data? This decides whether the engine's hand-built snapshot stays the record or whether Rapier's own serialization could carry the restore.
5. **T3 lint — memory.** For `wasm32-unknown-unknown` with Rust 1.98.1, which linker arguments fix the linear memory's maximum equal to its initial size and forbid `memory.grow` (`-C link-arg=--max-memory=N`, `--initial-memory`, `-Z` flags not allowed on stable), and what initial size does the solver crate need for 64 bodies, 64 colliders, a heightfield buffer, and the snapshot buffer? Does `std` or any dependency call `memory.grow` on its own through the allocator, and which allocator avoids it?
6. **T3 lint — opcodes.** The exact encoding of the relaxed-SIMD instructions in the binary format (the `0xfd` prefix and the LEB128 opcode range), and of `memory.grow` (`0x40`), so `solver/lint.mjs` can scan a module's code section without a full decoder. Also whether `-C target-feature=-relaxed-simd` alone guarantees none are emitted by the 1.98.1 backend.
7. **T4 outcome tests — CCD.** Under `enhanced-determinism`, is Rapier's continuous collision detection (`ccd_enabled(true)`, `IntegrationParameters` CCD fields) deterministic across platforms and runs, and does enabling it change the solver's state that the snapshot must carry (CCD solver state, predicted positions, substep bookkeeping)? What speed and thickness does Rapier's CCD guarantee against tunnelling for a cuboid against a static cuboid at `dt = 1/64`?
8. **T4 outcome tests — the character controller.** The exact semantics of `KinematicCharacterController` at 0.35.3 for autostep (`max_height`, `min_width`, `include_dynamic_bodies`), `max_slope_climb_angle`, `min_slope_slide_angle`, and `snap_to_ground`, with the comparisons used (strict or inclusive at the limit) so the course's "just below and just above" cases are set on the right side of each comparison.
