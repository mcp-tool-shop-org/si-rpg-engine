# Dispatch E2b — orientation and angular velocity

2026-09-25. Coordinator: Claude. Builder: the builder seat. Reviewer: a different family, on a scratch clone, before merge. Depends on E2, merged at `a097f44`. The plan names this as the first work after E2.

## What it is

E2 locked rotation so the frame contract and the fixtures kept their shape while the solver landed. That lock comes off for dynamic bodies. A body's record gains an orientation and an angular velocity, both hashed, both replayed, both drawn. The character stays a kinematic box with rotation locked; whether it becomes a capsule is decided here by a test, not by taste.

## Pins

1. **The record.** `Body` gains `qx, qy, qz, qw` (a unit quaternion, `w` last) and `wx, wy, wz` (angular velocity). `Frame`, the log, the host's frame record, and the debug view carry them. The hash mixes them after the six translational floats, in that order. The quaternion is renormalized by the solver, never by the tick.
2. **The lock comes off for dynamic bodies only.** Dynamic boxes rotate under contact. The kinematic character keeps `lock_rotations`. Static colliders have no orientation this slice; an oriented static box is E3's world record, not this one.
3. **Canonical orientation.** A quaternion and its negation are the same rotation. Before the hash, `w` is made non-negative by negating all four components when it is negative; `-0` is canonicalized as E2 does. A NaN in any of the seven new floats aborts the step, as it does for the six.
4. **The fixtures.** `fixtures/behavior-solver.json` cannot replay unchanged, because a box that tumbles moves differently. It is kept, its test becomes a boundary test with the tick where the first frame differs stated, and a new capture replaces it the same day: a box dropped on an edge so it tips, a box pushed off a ledge so it tumbles, and the stack from E2 still at rest. The product scene gains a tipping body so the golden covers rotation; `write-golden` rewrites `fixtures/golden.txt` once with the reason in the commit. The arithmetic golden does not move.
5. **The shape question is settled by a test, not an argument.** Build the same traversal fixture twice, once with the character as a box and once as a capsule of the same height and width: a step at the maximum height, a slope at the limit, a ledge edge, a narrow gap. Record what each shape does, in the pull request, as frames. The one that passes the step and the slope without walking off the ledge edge is the shape. If both pass, the box stays, because it is the shape the fixtures already hold. The decision and its evidence go in `docs/PHASE-1.md` as one sentence.
6. **The debug view** draws an oriented box as its projected outline, not an axis-aligned rectangle, and nothing else changes in it.
7. **The seat, the host, the goals.** The seat stays frozen; its grammar takes the new fields and is not run. The host's adapter is unchanged. `reachedGoal` reads position only.
