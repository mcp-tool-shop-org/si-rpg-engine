## Q1 — The split
ANSWER: Building the bench first is right (the research is explicit that the cheap proposer is the baseline, findings 3, 4, 5 at `docs/study-swarm/seat-instrument.dispatch.md:22-24`), but the draft fixes four shapes that T7c would have to undo:
1. **The candidate unit.** Pin 4 makes a candidate "a log of one to k intents" run from the load. The seat proposes one intent against one frame and settles (`packages/propose/seat.js:114-115`), and T7a's rails make a proposal cite `builtAt` and be re-checked on the current state (`docs/dispatch-t7a-seat-rails.md:136-146`). T6 already has the right unit: a witness (log to a settled cell) plus one action, with the state restorable from the archive (`wt-75/packages/load/sweep.js:104-105, 632-635`). If the bench's runner takes whole logs, T7c must retrofit "state + one intent" and re-derive the restore path; if the bench's runner takes (witness, intent) from the start, the grammar's k-intent logs are just k successive extensions and the model plugs in as one more extender.
2. **Feedback shape.** Pin 7 defines one report per run. T7c's model needs per-candidate feedback (what it reached, why refused, first difference) each round (`seat-instrument.dispatch.md:125`). If that record exists only in the final JSON, T7c refactors the ladder to emit it incrementally.
3. **The `access` input.** T7a's manifest names a source `access` (`dispatch-t7a-seat-rails.md:27`), but T7a is not on main, so nothing constrains the access map's shape. T7b should fix it as a JSON contract now: per anchor, the verbs that reached it and the cell (witness) they reached it from, because "how to reach the changed functions" was the largest single gain in finding 11 (`seat-instrument.dispatch.md:33`).
4. **The target space.** The seat's schema admits only point targets `{x, z}` (`packages/propose/schema.js:57-68`); the bench's grammar draws body targets too (pin 4). Unless the report partitions results by target kind, T7c's comparison is unfair in a way nobody can see; widening the schema is "reviewed like the law" (`dispatch-t7a-seat-rails.md:57`). *(Coordinator's check: this reads main's frozen seat. T7a's `schema.js` on #77 builds point, body, and zone targets from the catalog and the world, so the premise does not hold once T7a merges.)*

Also: the bench imports nothing from `packages/propose` (pin 10), good, but it should state the generator interface (`(feedback, seed) => candidate | null`) so the seat becomes a third generator without touching the ladder.
CHANGE IN THE DISPATCH: Pin 4, first sentence, to: "A candidate is a settled state the sweep archived (its witness) and one intent proposed from it; a generator is a function from the bench's feedback to a candidate, deterministic under a seed for the two built here. The grammar's longer logs are successive candidates." Pin 7: add "and a per-candidate record, written as each candidate finishes, holding its anchors reached, its admission on each build with reasons, and its first-difference block; the report is a summary of those records." Pin 2: add the access map's JSON shape and say it is the content of T7a's `access` source.

## Q2 — The ladder's order and its stops
ANSWER: Stopping at rung 1 is wrong, and the draft already contradicts itself: pin 3 says every admitted candidate runs on both builds; pin 5 says a candidate stops at the first rung it cannot reach, with rung 1 before rung 2. Coverage misses in four concrete ways:
- **Rule files.** `predicates/intents/*.json` are data read by `loadIntentRules` (`packages/tick/predicates.js:22-38`); no V8 block ever "overlaps" a JSON line. The draft names rule anchors (pin 1) but never says how rung 1 is decided for one.
- **Top-level lines.** `STEP_HEIGHT` (`predicates.js:10`), `DT`, `G`, `MAX_SPEED`, `UNDRIVEN_DRAG` (`packages/tick/world.js:8-13`), `SETTLE_QUANTA`, `REACHES` (`sweep.js:88, 94`), `PRODUCT_STEPS` (`packages/tick/sessions.js:25`) execute once at module load, never "around the run alone" (pin 2). Worse, pin 1 defines a JS anchor as "a function whose body holds a changed line", so a change to `STEP_HEIGHT`, which governs every climb admission (`predicates.js:143`), is not an anchor at all and is silently dropped from the report.
- **Deletions.** A removed line has no range in the head's text, so an anchor "named by the changed line ranges in the head's text" is empty; a dropped early `return` (pin 6's own operator) is exactly this.
- **The law.** Not measurable today (brief, pin 2 bracket); the draft says rung 2 stands in, which makes "reached" and "differs" the same thing for the law, so a behaviour-preserving law refactor is indistinguishable from an unreached one.

Yes, every admitted candidate should run on both builds; the base run is one replay, about 54 µs a quantum on the builder's machine (`wt-75/harness/corpus.mjs:627-628`). Rung 0 stays a gate (an unsound run is not a test input); rung 1 becomes a column. And rung 3 must be recorded on the base too, so "fails on head only" (a catch) is told from "fails on both" (a pre-existing finding).
CHANGE IN THE DISPATCH: Pin 5, "a candidate stops at the first rung it cannot reach" to: "Rung 0 is a gate. Rungs 1, 2, and 3 are recorded for every candidate rung 0 passes; rung 3 is recorded on both builds and a failure is a catch only when the base does not have it." Pin 1: add "A changed top-level line in `packages/tick/` or `packages/frame/` is an anchor; its reach is the coverage of every function in that file that names the declared identifier (a token scan, stated as approximate). A deletion is an anchor at the line it left behind, with no reach measured." Pin 2: add "A rule anchor is reached when its verb is submitted, admitted or refused."
CONFIDENCE: high

## Q3 — "Admission differs"
ANSWER: Sound only under a condition the draft does not state; without it, mostly noise. `submit` refuses any intent whose `frameHash` is not the current frame's (`packages/tick/tick.js:261-263`), and `logRun` throws at the first refused or mis-hashed entry (`packages/tick/runs.js:111-126`). So a candidate carrying head-recorded hashes, replayed on the base after any earlier divergence, is refused "stale frame" at its next intent: an "admission differs" that is a consequence of the earlier difference, not the checker's. Two rules make it sound: the bench submits each intent citing each build's own newest frame (the candidate is ticks and intents, not hashes), and admission is compared only while the two builds' frames still agree at the admission tick; the first disagreement of admission is the candidate's first difference, the comparison stops there, and it is attached to that one first-difference block rather than counted as a second difference. When the change is the checker itself (a rule file, `predicates.js`, or the world queries it calls: `supportAt`, `segmentHits`, `sleeping`, `overlaps`), that record is the signal, not noise. Two further sources of noise the draft should name: a refusal reason whose text changed but whose verdict did not is not a difference (the draft's wording already implies this; say it), and pick-up's refusal "the solver does not hold this world" (`packages/tick/predicates.js:206-210`, `world.js:832-843`) fires on whichever build happened to build another product world more recently, so the two processes must create worlds in the same order or that refusal shows as a false "admission differs". Note also that the draft's own F2 paragraph (pin 8) concedes that across real commits the checker drifts and would refuse what `main` admits; on a real PR that touches the checker, admission-differs will dominate the report, which is correct but must be summarised, not listed per candidate.
CHANGE IN THE DISPATCH: Pin 3, replace the last sentence with: "A candidate names its intents by tick; on each build the bench submits each one citing that build's newest frame. While the two builds' frames agree at an admission tick, a refusal on one and an admission on the other is the candidate's first difference, 'admission differs', naming the intent and both reasons; the comparison stops there. A refusal whose reason text alone differs is not a difference. A refused candidate is still submitted on the other build, so the reverse case is seen."
CONFIDENCE: high
BASIS: `packages/tick/tick.js:255-330`; `packages/tick/runs.js:103-148`; `packages/tick/predicates.js:206-210`; `packages/tick/world.js:822-843`; `packages/tick/bundle.js:515-517`.

## Q4 — The access map

A cheaper, truer aim already exists: T6's sweep visits every settled cell reachable by the action set, carrying states included (the cell key holds `carries`, `sweep.js:191-206`), and tries every verb from each (`sweep.js:608-620`); taking a coverage delta per admitted action during one ordinary sweep (13 s for crate-and-door, `wt-75/packages/load/world.js:11-19`) gives, for each anchor, the verbs that reached it and the cell they reached it from. That is the access map and the aim in one pass, at the sweep's own cost, and it is the "how to reach the changed functions" input finding 11 says pays most. Speculation on cost: a `takePreciseCoverage` per admitted action is the unmeasured part; if it is too slow, one delta per archived cell is the fallback.

An anchor no action reached in the whole sweep is named, with the load's own coverage checked separately. The aimed sweep of pin 4 explores from the cells the map names, not only from the load." ## Q5 — Mutants
ANSWER: The operators are the classic five and fine as far as they go, but "caught" and the score need repair:
- **The line.** "A candidate that reached its line" has no referent for a dropped return (the mutant tree lacks the line); define it as the head's changed range the mutant was made from.
- **Direction and rung 0.** Caught should be any separation, head-versus-mutant, in either direction of rung 3 as well as by trace, and a mutant that fails rung 0 (a nondeterministic or non-restorable mutant) is caught by rung 0, not "a finding of the tick".
- **Degenerate catches.** A mutant that throws at load or on every candidate's first quantum is "caught" by everything and inflates the score; report those as "fails before any candidate", beside "does not load".
- **Equivalent by construction.** One ulp on `0.3` changes `rise <= STEP_HEIGHT` (`predicates.js:143`) only at an exact tie, and 10% of `0` (`world.js:13`) is `0`; the draft's refusal to judge equivalence is right, but then a percentage is meaningless. Report caught and survived as lists with the operator and line, never a ratio, and let T7c compare generators on the same mutant list.
- **Coincidence with the base.** When the change is `<` to `<=`, the flipped-comparison mutant is the base's text; say when a mutant equals the base at its line, so rung 2 is not counted twice.
- **What makes it meaningless.** Fewer than a handful of mutable tokens on the changed lines; a rule anchor (no JS line; mutate the JSON value instead, or say no mutants); a mis-measured reach (Q2) shrinking the denominator; and a mutant tree that rebuilds the law when the change is JS-only (copy the head's `solver/dist/solver.mjs`, which is not committed, `solver/build.mjs:97`, into the mutant tree instead of rebuilding).

Mutating only the changed lines is enough for what it measures: whether the candidates are sensitive at the change. It does not measure the bench's aim (that is the access map's job) and the report should say so.
CHANGE IN THE DISPATCH: Pin 6: "A mutant is caught when a candidate that reached the head range it was made from separates the head and the mutant: a trace difference, a rung-3 failure on one and not the other, or a rung-0 failure. A mutant that does not load, or fails before any candidate acts, is listed and not scored. Mutants are reported as lists with operator and line, never a ratio; a mutant whose text equals the base's at that line is marked. A rule anchor's mutants move the rule's numbers by one ulp and 10%. A JS mutant tree takes the head's built binary."
CONFIDENCE: medium
BASIS: `packages/tick/predicates.js:76-85, 133-147`; `packages/tick/world.js:8-13`; `solver/build.mjs:97`; draft pin 6; finding 2 at `docs/study-swarm/seat-instrument.dispatch.md:21`.

## Q6 — Budgets and the stall rule
ANSWER: Equal wall-clock between two CPU generators is a defensible unit, but it breaks pin 7: if the budget is time, the set of candidates run before it ends depends on machine load, and "two runs with the same seed give the same report but for times" is false. The engine already has deterministic cost units, quanta and restores (`wt-75/packages/load/world.js:19`); budget in those, compare generators at equal quanta, and report wall time beside them. In T7c the model's budget is calls and seconds (`dispatch-t7a-seat-rails.md:150-152`) and the honest comparison is CodaMosa's, sweep alone against sweep-plus-model-at-stall at equal quanta with GPU time reported, not model against sweep at equal seconds. The stall rule as written cannot fire correctly: "no new difference" is undefined (every differing candidate's block has its own tick, so all are "new" and a change that differs never stalls, while a change that never differs stalls after the first n), and the sweep is finite and ordered breadth-first by cell (`sweep.js:601`), so a fixed n stalls it while carrying cells are still in the frontier. Two triggers instead: the aimed sweep stalls when its frontier empties or its budget is spent; the grammar stalls after n admitted candidates with no new changed line and no new (anchor, body, field) first difference. And T7b can measure n without a model: do not stop at the stall, keep going to the budget, and report how many new lines and differences came after the stall (a late-gain rate per n); that number is what T7c calls the model on.
CHANGE IN THE DISPATCH: Pin 7: "Comparisons between generators are made at equal budgets of quanta and restores; wall time is reported beside them." Pin 4: "A difference is new when its first-difference (anchor reached, body, field) has not been seen. The aimed sweep stops when its frontier empties or its budget is spent. The grammar stops after n admitted candidates with no new changed line and no new difference; the bench runs on past the stall to the budget and reports what came after it, per n, and T7c calls the model at the n that number justifies."
CONFIDENCE: high
BASIS: draft pins 4 and 7; `wt-75/packages/load/world.js:11-19`; `wt-75/packages/load/sweep.js:601-663`; `docs/dispatch-t7a-seat-rails.md:150-152`; findings 3-5 at `docs/study-swarm/seat-instrument.dispatch.md:22-24`.

## Q7 — What makes the bench lie
ANSWER: Concrete, in order of likelihood.
1. **One checker for two trees (false "no difference", vacuous pass).** `loadIntentRules` reads `predicates/intents/index.json` relative to the working directory, not the module (`packages/tick/predicates.js:23, 29`); so do `beliefs.js:18` and `packages/load/suite.js:32, 38`; `runs.js` caches the catalog once per module instance (`runs.js:37`). Two trees loaded in one process share one cwd, so both checkers read one tree's rules and pin 8's planted rule change is invisible; `load` itself pins cwd with `chdir(root)` (`wt-75/packages/load/bin/load.js:31-32`) precisely because of this. Pin 8's first test catches it only if the builder happens to run one process; a builder who runs two passes the test and ships a bench that lies the first time someone runs it the other way. Fix: one process per tree, cwd at the tree's root, runner imported by absolute path.
2. **Interleaved product worlds (false difference, spurious rung-0 red).** The solver is one instance per module (`solver/build.mjs:103-124`), `ensure` rebuilds Rapier's world whenever the world id changes (`solver/src/rapier_law.rs:341-350, 957-980`), and a rebuild wakes everything cold (`rapier_law.rs:385-423`); `restore.test.js` proves an evicted run no longer reruns the same (`wt-75/harness/restore.test.js:85-92, 800-808`). A bench that steps two ticks in lockstep, or builds an access-map world between a candidate's quanta, produces differences that are the bench's, and `sleeping` throws when the world is not held (`world.js:836-842`), which the sweep calls every settle (`sweep.js:414`). No pin-8 test catches this; rung 0's own red would fire and be misread as a tick finding. Fix: strictly one live product world per process, each run finished or restored before the next begins, held by a test that interleaves two and requires the bench to refuse.
3. **Worlds from the wrong tree (false difference).** A PR that edits a world or fixture file is "not an anchor", but if each tree runs its own copy, every candidate differs at tick 0 (body fields or `snap`, `difference.js:136-157`). Fix: worlds and fixtures are read from the head tree only, and a base whose file differs is reported as "world differs, not aimed at". No pin-8 test covers this.
4. **Trace-invisible changes (vacuous "no behaviour").** The trace holds body fields, zone, links, snapshot, goal-met flags, and the newest belief id (`packages/tick/trace-line.js:75-103`); the hash mixes the same plus `mixMinds` (`packages/tick/minds.js:174-189`). Episodes (`tick.js:293, 318`), belief contents, refusal reasons, hosts, and `log()` bookkeeping never reach either. A change in `admitEpisode` or `memory.recordEpisode` is "reached, no difference", identical to pin 8's rename-and-comment test. Fix: the report labels each anchor "observable in the trace: yes/no/unknown" by whether its function is on a path to hashed state, and pin 8 plants a change in the `use` episode's text and requires the bench to say "not observable", not "no difference".
5. **Mid-tick submission and the frame line.** `submit` sets the actor's velocity at once (`tick.js:306-307`) and the trace line reads `world.bodies` live; the bench must print each tick's line before submitting at that tick, or a same-build replay differs from its own run at the admission tick. Pin 8's determinism test would catch it, red, but as a rung-0 mystery.
6. **Coverage before it started.** V8's protocol documents (as I recall them, not read here) that data for code run before precise coverage was enabled may be incomplete and that `takePreciseCoverage` resets the counters; module top-level code runs at import, before any per-candidate window. This is Q2's constant problem in another form; the token-scan fix covers it.
7. **The hasher as the change.** A change to `packages/frame/hash.js` differs at tick 0 on every candidate; a fact, but the stall rule never fires and the report floods. Collapse "all candidates differ at tick 0 hash" into one line.
8. **Two binaries that should be one.** `solver/dist/solver.mjs` is not committed (`build.mjs:97`), so each tree builds; FLAGS.md says the host triple enters every crate's `-C metadata` (`solver/FLAGS.md:66-69`), and I speculate the worktree path enters the root crate's metadata too, so two trees may have different digests for identical law. The bench must not use digest equality as "same law"; run one fixed control input (the product scene, `sessions.js:127-213`) on both trees before any candidate and require identical traces when `solver/` has no diff, and copy the head's binary into a JS-only base to save the rebuild.
9. **The bundle's commit.** `commit()` runs `git rev-parse HEAD` in the tree (`packages/tick/bundle.js:187-197`); a planted copy reports `main`'s HEAD with an uncommitted plant. Record a tree digest in the report beside the commit.

Also: bundles from the head do not "replay on both builds" to a body-and-field block; on the base, `replayBundle` reports the hash chain's first mismatch only (`bundle.js:515-517`) and would refuse the log at the next entry (`runs.js:114-120`). The body-and-field block comes from the bench's own two traces (`difference.js:185-205`); say so in pin 5.
CHANGE IN THE DISPATCH: Add a pin, "Where the builds run": "Each tree runs in its own process with its working directory at the tree's root, the runner imported into it by absolute path from the bench; each process holds one live product world at a time and finishes or restores a run before beginning another; worlds, fixtures, and generators come from the head, with their digests in the report; before any candidate, a control run of the product scene on both trees must trace identically when `solver/` has no diff. ## Q8 — The planted F2 test
