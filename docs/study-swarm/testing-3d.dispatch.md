# Study-swarm dispatch: how professional studios test 3D, and what this engine tests next

> **Product being decided.** `si-rpg-engine` after Phase 1. Five engine slices are on `main`: the body record in three dimensions, the Rust-to-WebAssembly solver with rotation, content validated at load with zones, a verb table with climb, carry, release, and use, and minds that see and believe. The suite is 73 tests, two golden hashes under three JavaScript engines, seven behaviour fixtures that replay frame for frame, and a binary pinned by its Linux digest. The question is what a suite for a 3D simulation engine looks like at the studios and vendors who ship them today, and which of those tests this engine is missing.

Three research lanes ran in parallel on 2026-09-25, each on retrieval only: a source the lane could not fetch did not enter. Lane A: determinism, replay, and cross-platform reproducibility. Lane B: physics and collision regression. Lane C: automated gameplay and world testing. The Director's separate question, where the industry is heading, is answered in `product-alignment.dispatch.md` and does not touch this document.

## Step 1 — Load-bearing questions

- **QA Divergence.** When two runs disagree, how do shipping engines find the first differing step and the first differing field, and what do they check besides a hash?
- **QB Platforms.** Which platform, compiler, and instruction-set differences have actually broken determinism in shipped engines, and how does CI catch them?
- **QC Physics regression.** How do physics vendors regression-test collision, tunnelling, character controllers, and stability, and what is their policy when a golden legitimately moves?
- **QD Automation.** How do studios drive a 3D world automatically to find reachability defects, exploits, and regressions, and where does a language model belong in that loop?

## Research grounding (the dispatch's empirical floor)

### Lane A — determinism, replay, reproducibility

1. **Box2D's CI runs one determinism scene across MSVC, Clang, and GCC on x64 and ARM and checks two numbers: the step on which every body sleeps and a hash of the resting transforms; fused multiply-add, the platform `atan2f`, and fast-math were the three breakers.** Catto 2024, "Determinism", https://box2d.org/posts/2024/08/determinism/. Implication: a golden hash needs a behaviour number beside it that the hash cannot mask, and CI needs an ARM lane.
2. **Jolt's test tool validates a hash of every body's position and rotation and can replay a recorded state file comparing after every step, to catch drift between platforms.** Rouwé, "Performance Test", https://github.com/jrouwe/JoltPhysics/blob/master/Docs/PerformanceTest.md. Implication: keep the hash of every quantum, so a failure names the first quantum, not the last.
3. **Rapier guarantees cross-platform determinism only under stated conditions: same version, same order of insertion and removal, and starting values that do not come from `Math.sin` or `Math.cos`; it recommends hashing a world snapshot to confirm.** Dimforge, "Determinism", https://rapier.rs/docs/user_guides/javascript/determinism/. Implication: a load-time check that authored values are literals, and a test that insertion order changes the hash.
4. **WebAssembly 3.0 defines a deterministic profile that fixes every otherwise non-deterministic instruction result, including NaN bit patterns and relaxed SIMD, and names replayable systems as its use case.** Rossberg 2025, "Wasm 3.0 Completed", https://webassembly.org/news/2025-09-17-wasm-3.0/. Implication: lint the pinned binary for relaxed-SIMD instructions instead of trusting the build flag.
5. **Wasmtime lists non-determinism sources beyond floats: NaN bit patterns, relaxed SIMD, memory growth that may succeed or fail per host, and interruption timing, and fixes them with NaN canonicalisation and fixed memory limits.** Bytecode Alliance, "Deterministic Execution", https://docs.wasmtime.dev/examples-deterministic-wasm-execution.html. Implication: the solver's memory must not grow after load, and a test should prove it.
6. **GGPO's SyncTest rolls back one frame every frame and compares the full state, and its guide recommends running it throughout development; GGRS re-runs the last n frames and compares checksums.** Cannon, GGPO Developer Guide, https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md; GGRS, https://docs.rs/ggrs. Implication: the solver exports a snapshot but cannot load one; a restore-then-rerun test would expose state the snapshot misses.
7. **Unreal's networked physics uses error thresholds and resimulation from cached history, not bit-exact matching.** Epic Games, `NetworkPhysicsSettingsResimulation`, UE 5.4, https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/NetworkPhysicsSettingsResimulation?application_version=5.4. Implication: nothing to copy; bit-exact hashing is stricter than what the largest engine ships.
8. **An LLM-driven program generator found about 2.5 times as many cross-compiler floating-point differences as the earlier tool Varity, most of them ordinary value differences rather than NaN or infinity.** Wang and Rubio-González 2025, "LLM4FP", arXiv:2509.00256. Implication: a NaN check does not prove agreement; a toolchain bump is a change to the golden and is treated as one.
9. **Factorio's suite checks a CRC after every test against saved values that are regenerated on purpose when game logic changes.** Wube 2014, FFF-60, https://factorio.com/blog/post/fff-60. Implication: a golden rewrite is a named event with a stated reason, which this repository already does in commit messages.

### Lane B — physics and collision regression

10. **Box2D's determinism test asserts the sleep step and a transform hash across 1–15 worker threads and the built-in scheduler, and the author rewrites the numbers on purpose when the engine changes.** Catto, `test/test_determinism.c`, https://github.com/erincatto/box2d/blob/main/test/test_determinism.c. Implication: same as 1, and the rewrite policy is explicit.
11. **Jolt hashes named scenes on about fifteen compiler and architecture targets including WebAssembly, and its unit tests compare 0 worker threads against 15 body by body and field by field every step.** Rouwé, `determinism_check.yml` and `UnitTests/Physics/PhysicsDeterminismTests.cpp`, https://github.com/jrouwe/JoltPhysics. Implication: per-body field comparison gives the first diverging field, and fast-mover and character scenes need their own goldens.
12. **Rapier's snapshot golden is a pair, byte size plus an FNV digest; it caught `usize` sentinels encoding differently on 32-bit wasm, and an ARM64 CI job caught a signed-zero difference in min/max ties that x86 had missed for months; its thread-count test also records the order of collision events.** Dimforge, `tests/snapshot_portability.rs`, `thread_count_determinism.rs`, `rapier-ci-build.yml`, https://github.com/dimforge/rapier. Implication: store size plus digest, hash event order apart from body state, and run ARM.
13. **Rapier writes one permanent test per bug report, named after the issue and asserting the outcome: a thin tilted slab stays above a trimesh, cubes do not tunnel a thin cylinder, a heightfield seam holds, the character depenetrates, a large-dt CCD step does not hitch, a zero-dt step is safe.** Dimforge, `crates/rapier3d/tests/`, https://github.com/dimforge/rapier. Implication: every defect this engine finds becomes an issue-named outcome test, not a hash.
14. **Jolt's character tests assert positions computed by formula: slopes from 5° to 85° at 1e-4 tolerance, stairs at 60–360 Hz, stairs beside a wall, a rotating platform, a character starting inside geometry, character against character.** Rouwé, `UnitTests/Physics/CharacterVirtualTests.cpp`, https://github.com/jrouwe/JoltPhysics. Implication: a course built around this engine's own limits, checked just below and just above each.
15. **Box2D checks that a pyramid built at a 1e7 offset follows the same relative path and sleeps on the same frame as one at the origin, tests its character mover in a corner, a wedge, at its push limit, and against overshooting the floor, and turns away invalid input.** Catto, `test/test_large_world.c`, `test_mover.c`, `test_invalid_input.c`, https://github.com/erincatto/box2d. Implication: translate-the-whole-scene is a behaviour-preserving check the engine lacks.
16. **Rapier's character controller regressed in the 0.35 rework with a panic that 0.32 had handled.** Dimforge issue #1009, 2026, https://github.com/dimforge/rapier/issues/1009. Implication: any bump of the pinned solver reruns the character course before the golden may move.

### Lane C — automated gameplay and world testing

17. **Riot logs changed state every frame, replays 2,000–3,000 real games a day on server-matched hardware, and a script reports the first point two runs disagree; an uninitialised variable was found in about twenty bisection steps.** Hoskinson 2018, "Determinism in League of Legends: Fixing Divergences", https://www.riotgames.com/en/news/determinism-league-legends-fixing-divergences. Implication: a nightly replay corpus with automatic first-differing-quantum reporting.
18. **In a study of twenty experienced developers, 35.1% of debugging time went to reproducing the bug and 36.6% to examining artifacts.** Pinto Gomez and Petrillo 2025, "Identifying Video Game Debugging Bottlenecks", arXiv:2510.08834. Implication: every failing run writes a bundle of seed, input log, and hash chain that replays with one command.
19. **Go-Explore guided by the navmesh covered a 1.5 km square world in ten hours on one machine and found fall-through-floor bugs with no human demonstrations, beating curiosity-driven reinforcement learning.** Lu, Georgescu, and Verwey 2022, arXiv:2209.00570. Implication: snapshot restore makes cell-based exploration cheap; a reachability sweep compares where a body can get with what the zones say.
20. **Walkable space rebuilt from voxelised geometry checked against the navmesh's own answers finds navmesh defects, with reinforcement learning pointing the sampling at likely disagreements.** Raghavan et al. 2026, arXiv:2605.21397. Implication: a load-time hazard that compares traversal through the binary with the authored zones.
21. **EA added an experimental reinforcement-learning system to an existing automated testing solution built on scripted bots, to raise test coverage in Battlefield 2042 and Dead Space (2023), and reports that the development environment differing from the final product is a main reason research is hard to take to production.** Gillberg et al. 2023, arXiv:2307.11105. Implication: agents drive the pinned binary that ships, never a test build of it. The lane also read Fuchs et al. 2026, arXiv:2607.07498, reporting six diverse scoring exploits found in one experiment; that claim is body-level and not confirmed by the gate, so it is not load-bearing here.
22. **LLM test agents run in real QA pipelines: TITAN completed 95% of tasks, found four unknown bugs, and was deployed in eight pipelines; SMART reads code diffs to steer reinforcement learning to over 94% branch coverage of changed code.** Wang et al. 2025, arXiv:2509.22170; Mu et al. 2025, arXiv:2512.12706. Implication: a model proposes test intents aimed at changed code; the verdict stays with the checker and the hash.
23. **VideoGameQA-Bench is a benchmark of game quality-assurance tasks for vision-language models, covering visual unit testing, visual regression, and glitch detection among others, built because existing benchmarks could not say whether those models handle real QA scenarios.** Taesiri et al. 2025, "VideoGameQA-Bench", arXiv:2505.15952. Implication: the debug view is checked by fixed-camera capture and exact comparison; whether a vision model can judge it is an open question with a benchmark, not a settled one. The lane's read of the body put the best model at 45.2% on visual regression and 82.8% on glitch detection; those numbers are not confirmed by the gate and are not load-bearing.
24. **Risk-based test selection cut testing hours by 55% or more on a shipped title, flagging bug-inducing changes with 71% precision and 77% recall.** Senchenko et al. 2022, "SUPERNOVA", arXiv:2203.05566. Implication: which fixtures and sweeps run per commit follows which subsystem the diff touched.
25. **Open-world games are used as an extreme case of where closed-world testing assumptions fail, with inexhaustible behaviour spaces, non-deterministic execution outcomes, elusive behavioural boundaries, and unstable test oracles as the recurring characteristics.** Kato et al. 2026, arXiv:2604.04047. Implication: this engine removed the first; its next work is the oracle, which here is the checker plus the hash.

## Step 5 — What the engine tests next

Each item names the findings it rests on. Together they are the proposed Phase 2, "the suite", for the Director to order.

- **T1 The hash stream and the first difference.** Every fixture already stores a hash per frame. The harness gains a per-quantum diff that names the first differing quantum and, within it, the first differing body and field, and the golden check prints both on failure. (2, 11, 17)
- **T2 A behaviour number beside every golden.** The product golden and each fixture record the sleep quantum of every dynamic body and the resting height of the stack, asserted with the hash; a golden rewrite must state which number moved and why. (1, 9, 10)
- **T3 Restore from a snapshot.** The solver gains `solver_restore`, and a test loads a mid-run snapshot, reruns from there, and requires the same hash stream to the end; that is the test that finds state the snapshot misses. (6, 12)
- **T4 Platforms and the binary.** CI adds an ARM64 lane running the same three engines; a lint refuses a binary containing relaxed-SIMD opcodes or a memory that can grow after load; the snapshot golden becomes size plus digest, and event order is hashed apart from bodies. (1, 4, 5, 12)
- **T5 Outcome tests, issue-named.** A thin fast body against a thin slab, a heightfield seam, a whole-scene translation by 1e6, and a character course at this engine's limits: a step of 0.29 and 0.31, a slope of 44° and 46°, a snap at and past 0.2, a character starting inside geometry, a character against a character. Each asserts the outcome, not a hash. Any solver bump reruns the course first. (13, 14, 15, 16)
- **T6 The replay corpus.** A nightly job replays every log the repository holds against the current build and every fixture, and a failing run writes a bundle of seed, world, log, and hash chain that `replay` reproduces in one command. (17, 18, 24)
- **T7 The reachability sweep.** Using T3's restore, a sweep explores from every settled cell of a world and compares the zones a body can reach with the zones the file authored, as a load-time hazard when a world is small and as a nightly job when it is not. (19, 20)
- **T8 The seat as a test instrument.** The frozen proposer seat thaws only as a source of test intents aimed at changed code, run through the checker, with the verdict from the hash and the outcome tests, never from the model. Agents drive the pinned binary. (21, 22, 25)

## Not in this dispatch

No vision model judging the debug view (23 is a benchmark, not a licence). No error thresholds in place of bit-exact agreement (7). No test whose oracle is a model (25).
