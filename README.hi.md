si-rpg-इंजन 3D दुनिया के लिए एक सिमुलेशन कोर है जो बिल्कुल उसी तरह से फिर से चलता है। यह प्रति सेकंड 64 चरणों पर भौतिकी को लागू करता है, प्रत्येक चरण के बाद दुनिया की एक फ़िंगरप्रिंट रिकॉर्ड करता है, और इसके शुरुआती बीज और स्वीकार किए गए इनपुट से किसी भी रन को बिट दर बिट फिर से बना सकता है। भौतिकी को रस्ट में संकलित किया गया है और इसे एक WebAssembly फ़ाइल में बनाया गया है। एक भाषा मॉडल सुझाव दे सकता है कि आगे क्या होता है; हाथ से लिखे नियम तय करते हैं कि क्या शामिल किया जाता है। यह [ai-rpg-इंजन](https://github.com/mcp-tool-shop-org/ai-rpg-इंजन) का समकक्ष है, और इसे इस बात से मापा जाता है कि यह क्या अनुकरण करता है।

## यह क्या है, और यह क्या बनने का लक्ष्य रखता है

क्रोम, फ़ायरफ़ॉक्स और सफारी के पीछे के जावास्क्रिप्ट इंजन, जो V8, स्पाइडरमंकी और जावास्क्रिप्टकोर हैं, प्रत्येक कमिट पर एक ही दुनिया के लिए समान फ़िंगरप्रिंट प्रिंट करते हैं, और समान भौतिकी निर्माण इसे x64 और ARM64 पर प्रिंट करता है। बाकी सब कुछ उस वादे पर निर्भर करता है: दो मशीनें एक दुनिया के बारे में, एक बीज और स्वीकार किए गए इनपुट की सूची को देखते हुए, बाइट दर बाइट सहमत हैं। इसके ऊपर ऐसे निकाय हैं जो तीन आयामों में गिरते, फिसलते, धकेलते, मुड़ते और लुढ़कते हैं; एक चरित्र जो कदम रखता है, ढलानों पर चढ़ता है, चीजें ले जाता है और उन्हें नीचे रखता है; दुनिया की फाइलें जिन्हें गलत होने पर एक कारण के साथ अस्वीकार कर दिया जाता है; और ऐसे पात्र जिनके दिमाग होते हैं जो देखते हैं, याद रखते हैं कि उन्होंने क्या देखा, और पुराने सबूतों के आधार पर किसी विश्वास को अस्वीकार करते हैं, बजाय इसके कि वह क्या बदल देगा।

यह क्या बनने का लक्ष्य रखता है, वह एक होस्ट के अंदर सिमुलेशन कोर है: एक ब्राउज़र, गॉडोट, या अनरियल चित्र बनाता है और इनपुट भेजता है, जबकि भौतिकी, फ़िंगरप्रिंट और रिकॉर्ड यहां रहते हैं। वर्तमान कार्य एक परीक्षण सूट है जिसकी एक शिपिंग इंजन को आवश्यकता होती है, और इसका अधिकांश भाग इसमें है: एक ट्रेस जो पहले चरण और मान को नाम देता है जहां दो रन अलग हो जाते हैं, एक सटीक साबित होने वाला सहेजें और पुनर्स्थापित करें, एक दूसरा CPU आर्किटेक्चर, संकलित भौतिकी पर एक लिंट, और परीक्षण जो यह जांचते हैं कि दुनिया ने क्या किया, न कि केवल इसकी फ़िंगरप्रिंट। मेश से टकराव इसमें है: एक दृश्य एक निश्चित त्रिकोणीय मेश को नाम दे सकता है, और उत्पाद दृश्य में कोई भी नहीं है। होस्ट [docs/host-binding.md](docs/host-binding.md) में सॉकेट से जुड़ता है। डिज़ाइन और योजनाएं [docs/PHASE-0.md](docs/PHASE-0.md), [docs/PHASE-1.md](docs/PHASE-1.md), और [docs/PHASE-2.md](docs/PHASE-2.md) में हैं।

## स्थापित करें

आवश्यकताएँ: नोड 20 या नया, और भौतिकी निर्माण के लिए `wasm32-unknown-unknown` लक्ष्य के साथ रस्ट टूलचेन। सीआई रस्ट 1.98.1 को पिन करता है; `rustup target add wasm32-unknown-unknown` रस्टअप स्थापित करने के बाद एक अतिरिक्त चरण है।

```bash
git clone https://github.com/mcp-tool-shop-org/si-rpg-engine.git
cd si-rpg-engine
npm ci
npm run verify     # typecheck, the suite, both goldens, and the behaviour numbers under node
```

`npm test` पहले भौतिकी बनाता है और बाइनरी को लिंट करता है। लिनक्स पर, निर्माण को पिन किए गए डाइजेस्ट से तुलना की जाती है; किसी अन्य होस्ट पर, यह अपना डाइजेस्ट रिपोर्ट करता है, क्योंकि लिनक्स निर्माण पिन किया गया कलाकृति है।

## उपयोग करें

प्रत्येक कमांड किसी भी निर्देशिका से चलता है, `--help` का उत्तर देता है, सफलता पर 0 से बाहर निकलता है, इनकार पर 1 के साथ एक कारण देता है, और उपयोग त्रुटि या अप्रत्याशित विफलता पर 2। `--debug` एक स्टैक ट्रेस को गुजरने देता है।

```bash
npx play proposals.json --seed 7 --log out.json    # run proposals through the tick and print every committed frame
npx replay out.json                                 # rerun a log; fails on the first hash that differs
npx replay fixtures/corpus/product-rebuild-261.bundle.json   # rerun a bundle to its save tick, compare every hash, and restore its memory image
npx load world worlds/crate-and-door.json           # validate a world, run its hazards, sweep its reachable states, and write its load hash to the index
npx load admit fixtures/climb-draft.json            # compile an action draft, run the hazards for its effect, and add it to the catalog
npx load retire climb                               # take an action out of the catalog
npx host --world worlds/crate-and-door.json         # serve the debug view at http://127.0.0.1:4173
npx write-golden                                    # run the course and outcome tests, then rewrite the goldens and name what moved
```

जब दो रन असहमत होते हैं, तो ट्रेस बताता है कि कहां:

```bash
node harness/trace.mjs > a.trace                    # the product scene, one line per step in exact bits
node harness/first-difference.js a.trace b.trace    # identical, or the first step, body, and field that differ
node solver/lint.mjs                                # refuse a binary that could grow memory or let the host choose a result
```

किसी परिवर्तन को उससे पहले के निर्माण के विरुद्ध मापा जा सकता है। बेंच हाथ से चलता है, और कोई वर्कफ़्लो इसे नहीं चलाता है:

```bash
npx bench trees . main HEAD ../trees                # the base and the head as git worktrees, the head's binary built in its own tree
npx bench anchors --base ../trees/base --head ../trees/head    # the code and data the change touches, as JSON
npx bench run --base ../trees/base --head ../trees/head --out ../bench --product-scene    # reach, differences, and catches, with a report
```

रिपोर्ट अपने सीड का नाम देती है, क्वांटम और पुनर्स्थापना में अपने बजट की गणना करती है, और बताती है कि उसने क्या नहीं मापा; एक ही सीड के साथ दो रन अपने पर्यावरण ब्लॉक के बाहर समान रिपोर्ट देते हैं। जब `solver/` बदलता है, तो प्रत्येक ट्री अपनी स्वयं की बाइनरी बनाता है, और कानून की पहुंच एक कवरेज बिल्ड से आती है, जिसका रन उत्पाद दृश्य को ठीक उसी तरह चलाना चाहिए जैसे उत्पाद बिल्ड करता है, या बेंच कारण के साथ बंद हो जाता है।

एक दुनिया तीन तरीकों से पुनर्स्थापित होती है, और कोई भी भौतिकी इंजन की आंतरिक स्थिति में नहीं लिखता है, यही कारण है कि प्रत्येक सटीक है। आप इसके स्वीकृत इनपुट को एक चरण तक पुन: प्ले कर सकते हैं। आप भौतिकी मॉड्यूल की पूरी मेमोरी को `imageSolver()` के साथ कॉपी कर सकते हैं और इसे `restoreImage()` के साथ वापस रख सकते हैं। या आप पूरे टिक को `save()` के साथ सहेज सकते हैं और इसे `restore(saved)` के साथ वापस रख सकते हैं, जिसके लिए पुन: प्ले की आवश्यकता नहीं होती है और यह वह तरीका है जिससे स्वीप हजारों बार एक स्थिति में वापस आ जाता है। किसी अन्य बाइनरी से एक छवि, गलत लंबाई की, या एक परिवर्तित बाइट के साथ अस्वीकार कर दी जाती है, और एक सहेज जो पूरे परिवर्तनों की जांच नहीं करता है, कुछ भी नहीं बदलता है।

डीबग दृश्य एक डीबग दृश्य है। यह प्रतिबद्ध फ्रेम को `x`, `y`, या `z` के साथ चुने गए अक्ष के साथ प्रक्षेपित बक्से के रूप में खींचता है; एक क्लिक एक ग्राउंड-प्लेन लक्ष्य है; `M`, `C`, `G`, `D`, और `U` क्रमशः स्थानांतरित, चढ़ाई, उठाना, गिराना और उपयोग करना चुनते हैं; वॉकर का क्षेत्र और प्रत्येक मन की मान्यता टिक और हैश के बगल में बैठती है। यह कभी भी कुछ भी नहीं खींचता है जो टिक में नहीं है।

एक विश्व फ़ाइल JSON है: `name`, `seed`, `bodies`, `colliders`, `zones`, और वैकल्पिक रूप से `heightfield`, `mesh`, और `goal`। एक मेश `{ positions, indices }` है। एक बॉडी `{ id, x, y, z, vx, vy, vz, hx, hy, hz }` है जिसमें एक वैकल्पिक चतुर्भुज और कोणीय वेग होता है; एक स्थिर कोलाइडर इसके सीमाओं द्वारा एक बॉक्स है जिसमें एक वैकल्पिक चतुर्भुज इसके केंद्र के बारे में होता है; एक क्षेत्र एक नामित बॉक्स है। अज्ञात फ़ील्ड, डुप्लिकेट आईडी, अतिव्यापी बॉडी, एक बॉडी एक कोलाइडर के अंदर, एक गैर-इकाई चतुर्भुज, एक पतित या दुर्गम क्षेत्र, और एक लक्ष्य जो कुछ भी नाम नहीं देता है, प्रत्येक को एक कारण के साथ अस्वीकार कर दिया जाता है।

## कानून, एक सांस में

एक सीडेड टिक कानून है। एक संचालित बॉडी और एक गतिशील बॉडी एक ही सॉल्वर संपर्क साझा नहीं करते हैं, और संकीर्ण चरण अभी भी जोड़ी को ढूंढता है। एक चरण, एक क्वांटम, 1/64 सेकंड है; प्रत्येक चरण हैश किया जाता है, और एक चरित्र की क्रिया कई चरणों तक फैली होती है। पुन: प्ले सीड और उस चीज़ के लॉग है जो स्वीकार किया गया था। मॉडल इरादों, टाइप किए गए विश्वासों और बॉडी ड्राफ्ट का प्रस्ताव करता है; उस वर्ग के लिए चेकर उन्हें स्वीकार या अस्वीकार करता है। कार्रवाई ड्राफ्ट और विश्व फ़ाइलें लोड समय तक प्रतीक्षा करती हैं और एक खतरे सूट से गुजरती हैं। होस्ट प्रतिबद्ध फ्रेम प्राप्त करता है और इरादे लौटाता है। प्रस्तुति में हैश में वापस जाने का कोई रास्ता नहीं है।

## ट्रस्ट मॉडल

इंजन स्थानीय रूप से चलता है और केवल अपनी चेकआउट निर्देशिका के अंदर की फ़ाइलों को एक्सेस करता है: दुनिया, क्रिया ड्राफ्ट, फिक्स्चर और कोई भी लॉग जिसे आप किसी कमांड से लिखने के लिए कहते हैं। `host` केवल `127.0.0.1` को बाध्य करता है। `bench` चेकआउट का अपवाद है: यह अपने ट्री और अपनी रिपोर्ट को उस स्थान पर लिखता है जहाँ आप इसे इंगित करते हैं, और प्रत्येक ट्री को अपनी स्वयं की चाइल्ड प्रक्रिया में चलाता है। कोई भी कमांड `propose` के अलावा किसी अन्य सॉकेट को नहीं खोलता है, जो एक स्थानीय ओलामा सर्वर से बात करता है और कहीं और नहीं, और केवल उस भूमिका के लिए जिसका मेनिफेस्ट एक खाली दुनिया में कार्य करने के लिए सक्रिय किया गया है; इंजन द्वारा घोषित दोनों भूमिकाएँ स्थिर हैं, इसलिए यह किसी भी मॉडल क्लाइंट के लोड होने से पहले इनकार कर देता है। किसी मॉडल का प्रस्ताव केवल भूमिका गेट के माध्यम से दुनिया में प्रवेश करता है, जो इसे उसकी भूमिका के मेनिफेस्ट तक सीमित रखता है। किसी ट्री के भौतिकी को बनाने के लिए, `bench` `cargo build --locked` चलाता है, जैसे कि सॉल्वर की अपनी बिल्ड करता है, और कार्गो केवल तभी crates.io से एक पिन की गई क्रेट प्राप्त करता है जब उसकी कैश में वह क्रेट उपलब्ध नहीं होती है। कोई भी क्रेडेंशियल नहीं पढ़ा, संग्रहीत या भेजा जाता है। कोई टेलीमेट्री एकत्र नहीं की जाती है। लेखक द्वारा बनाई गई सामग्री अविश्वसनीय है और लोड होने पर मान्य की जाती है; अस्वीकृत फ़ाइल कुछ भी नहीं बदलती है। वेबअसेंबली बाइनरी को सीआई में स्रोत से बनाया जाता है और इसके SHA-256 द्वारा पिन किया जाता है, इसे कभी भी बाइट्स के रूप में कमिट नहीं किया जाता है। इसकी मेमोरी 32 MiB पर स्थिर है और यह नहीं बढ़ सकती है, इसलिए बहुत घनी दुनिया के लिए यह हर होस्ट पर उसी तरह रुक जाती है, बजाय इसके कि यह अलग हो जाए। [SECURITY.md](SECURITY.md) देखें।
